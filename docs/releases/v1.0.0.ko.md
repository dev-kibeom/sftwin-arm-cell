# SF-Twin ARM Cell v1.0.0 릴리즈 노트

v0.3.4 이후의 Robot·Tool·Cell 조립 구조와 호스트 런처, Vision/PICK 개선을 묶은 첫 1.0 기준선입니다. 엔지니어링·시뮬레이션 릴리즈이며 생산 설비 또는 안전 인증을 의미하지 않습니다.

## v0.3.4 이후 변경

### Robot·Tool·Cell 구성과 Isaac 런타임 (#50, #56, #64–#73)
- Bringup이 컴포넌트별 설정을 조립·검증하고 Isaac과 ROS에 동일 runtime snapshot을 전달합니다. 모델 선택과 검증용 조합을 명시적으로 구분합니다.
- Robot·Tool·Cell과 Model Assembly의 identity, 관절 순서, 경로 및 설정 계약을 검증하고 잘못된 절대 Prim binding을 거부합니다.
- Motion의 로봇 모델·관절 정책, Tool 접촉·충돌·파지 설정, Cell 소유 PICK clearance 및 위치 참조를 선택된 구성에서 소비합니다.
- Isaac의 Assembly 기반 URDF/USD 빌드, Cell scene 선택과 배치, Robot articulation/HOME/drive binding, Tool 구동·capture, Camera·자재 공급 binding 및 공통 runtime 생명주기를 통합합니다.
- 자재 공급 지지면은 공유 geometry에서 유도하고 공급 profile을 export합니다. 임의 Robot/Tool 교차 조합 지원을 의미하지 않습니다.

### RB5-850E와 Cell 배치 (#75–#77)
- 고정된 공식 upstream 모델을 기반으로 RB5-850E + Robotiq 2F-85 조합을 추가합니다. 기존 M0609 조합도 유지합니다.
- URDF effort를 보존하면서 시뮬레이션 전용 maxForce=1000과 damping=50을 적용해 하중 유지와 이동 후 진동을 조정합니다. 제조사 정격 torque나 실물 제어 gain이 아닙니다.
- RB5 HOME은 사용자 지정 0, 0, 90, 0, 90, 0도입니다. Return/Retract는 기존 값을 유지하며 제조사 공통 HOME으로 주장하지 않습니다.
- Cell과 런처 표시 이름은 PnP_CNC입니다. 내부 Prim 경로는 호환성을 위해 유지합니다.
- Boom을 TopBeam 위로 옮기고 뒤쪽 ㄱ자 브래킷과 Boom 위 CableTray를 배치했습니다. 카메라 광학 자세는 유지하며 MoveIt 충돌 형상도 동기화했습니다.

### Vision·파지·자재 처리 (#44–#55, #57)
- plane map에서 경사진 직육면체를 복원하고 로봇 PICK 후보로 연결합니다. 정규화된 Vision 진단과 snapshot 기하 정보를 정리합니다.
- Tray 경계를 넘는 관측과 측정 plane 후보를 보존하고, ROI 높이·자재 크기에 따라 height grid 확장을 제한합니다. 자재 target ROI와 Tray calibration 경계를 분리합니다.
- 경계 추출에서 급격한 높이 연속성을 보존하고 손가락 여유가 넓은 파지 자세를 우선합니다.
- 카탈로그 기반 CNC 자재와 선택형 공급을 추가하고 depth profile 처리를 분리해 설정된 직육면체 자재를 처리합니다.
- 그리퍼 aperture에 따라 파지 폭 적합성을 판단하고 설정된 Vision target profile을 수용합니다.
- Tray 안정화 시간 조건을 충족해야 검출하도록 보완합니다.
- 그리퍼 OPEN 이후 자재 물리 처리를 공통화하고 detach 후 중력을 켠 자재를 wake하여 떠 있는 현상을 수정합니다.
- gantry 및 상태 표시 하드웨어 정렬과 관련 경고를 정리합니다 (#49).

### 호스트 GUI 런처·개발 환경 (#58–#63, #74)
- 루트 `python3 launcher.py` 진입점과 선택적 venv 설치 절차, 재정리한 한·영 실행 안내를 제공합니다. 초기 GUI 도입·되돌림 이후 현재의 임시 snapshot 기반 실행으로 정리됐습니다.
- 지원되는 Profile 조합 선택, Isaac/ROS 시작·종료, 중복 실행 차단과 프로세스 정리, 오류·상태 표시를 제공합니다.
- 실행별 OS 임시 snapshot 하나를 Isaac과 ROS가 공유하고 소비 프로세스 종료 후 정리합니다. 원본 Profile과 영속 진단 기록을 실행용 임시 자원과 분리합니다.
- xterm 실행 터미널과 ROS debug 선택을 제공하며 Qt 버전 및 시스템 의존성을 정리합니다.
- 남은 ROS bringup 프로세스의 소유 관계를 확인하고 stale 실행을 정리합니다. 보호된 process cwd 조회를 처리하고 중복 CI 실행을 줄입니다.

## 업그레이드
- 전체 소스를 갱신하고 ROS workspace를 재빌드한 뒤 overlay를 다시 source하세요. Docker는 `docker compose up --build`를 사용합니다.
- GUI 사용자는 README의 Qt/xterm 설치 절차를 따르고 런처를 재시작하세요. Isaac 초기화 완료 후 ROS를 시작합니다.
- 기존 runtime export를 재사용하지 말고 선택된 Profile에서 새 snapshot을 생성하세요. 새 RB5 Assembly를 처음 사용할 때는 Pre Build로 USD를 생성합니다.
- 기존 사용자 설정은 컴포넌트별 Robot·Tool·Cell 및 Assembly 구성과 비교해 옮기세요. 과거 schema를 자동 변환한다고 보장하지 않습니다.
- 기존 실행 기록은 자동 이동하지 않습니다. `.run_records`와 관측 기록 계약은 관련 문서를 따릅니다.

## 검증과 제한
- 사용자 라이브 관측: RB5 자세 유지, 감쇠 적용 후 진동 개선, 카메라 지지대 배치 및 PnP 수행을 확인했습니다. 정량 성능 계측이나 전 작업영역 검증으로 확대 해석하지 않습니다.
- 직전 구현에서 Robot binding, scene authoring/composition, camera ownership, launcher 및 model composition 집중 테스트가 통과했습니다. 릴리즈 문서 갱신은 전체 ROS 빌드·Isaac 실행을 다시 수행하지 않습니다.
- 전체 Stop/Reset·E-Stop 복구, 실물 로봇 운전과 안전 등급 E-stop/STO 하드웨어 검증 완료는 주장하지 않습니다.
- 다른 Robot/Tool 조합, 모든 자재·경로의 성공을 보장하지 않습니다. 배포 Profile과 실제 adapter가 지원하는 조합을 사용하세요.
