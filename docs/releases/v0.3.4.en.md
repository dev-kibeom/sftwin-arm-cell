# SF-Twin ARM Cell v0.3.4 Release Notes

> v0.3.4 is an engineering and simulation release improving Vision/PICK candidate selection, PLACE recovery with attached payloads, per-run records, and runtime observability.

## Changes since v0.3.3

- **Vision and PICK search:** Prioritize supported stack tops and accessible grasp poses, and exhaust configured PICK pose search rounds. Improve inclined support classification from Tray overlap and final cuboid hypothesis selection, while preserving replay evidence for LOW candidates.
- **PLACE recovery:** Add planning and validation with attached payload geometry. When PLACE candidates are exhausted while holding material, retry via a planned home motion, once by default. Allow held payload contact with the gripper inner knuckles.
- **Planning and logging:** Reduce planning latency and retain phase diagnostics. Report task progress and results on the console while preserving detailed diagnostic records.
- **Unified per-run records:** Configure the record root and diagnostic/snapshot directories in `config/run_records.yaml`. Group connected records in shared run directories and reuse the initialization run for the first live test. Clarify diagnostic field names and interpretation rules while preserving legacy reader compatibility.
- **Isaac camera and environment:** Bundle local D455 assets and load prepared assets before Play. Manage D455 calibration explicitly, widen the Tray view, and increase camera support clearance beside the robot.
- **Local builds:** `ros2_ws/build-local.bash` builds the same TRAC-IK revision as the Dockerfile and configures the ROS workspace.

## Upgrading

- ROS interfaces and runtimes changed together. Update the full ROS workspace and Isaac runtime together. Docker Compose users should rebuild from the repository root with `docker compose up --build`.
- For host builds, follow the README procedure using `bash ros2_ws/build-local.bash`.
- Records default to `.run_records`; change paths in `config/run_records.yaml`. Existing records are not migrated automatically. For Docker, follow the README instructions for UID/GID configuration and record directory ownership.
- Update custom diagnostic analysis tools against the field names and interpretation rules in the [observability records ICD](../design/interfaces/icd-observability-records.md).
- See [payload home recovery](../design/components/motion/place-payload-recovery.md) for PLACE retries and return behavior. The existing final material return motion is excluded from collision checking.

## Verification and known limitations

- This release documentation update ran the CI-equivalent ROS package MIT metadata and Isaac Python syntax checks, plus relative-link and diff whitespace checks for the changed documents.
- The full ROS build/test suite and live Isaac Mission acceptance were not rerun for this update. The v0.3.3 test counts are not verification results for this release.
- Physical-robot operation and safety-rated E-stop/STO hardware verification are outside this release's scope.
