# SF-Twin ARM Cell v0.3.2 릴리즈 노트

> v0.3.2는 ROS 소스 구조와 공통 로봇 자산의 소유권을 정리한 엔지니어링 및 시뮬레이션 릴리즈입니다.

## v0.3.1 이후 주요 변경

- **잔여 구현 제거:** 이름 변경 이후 남아 있던 `arm_cell_motion_moveit2`, `arm_cell_orchestration_bt`(패키지명 `arm_cell_bt`), `arm_cell_integration`을 제거했습니다. 현재 Motion·Task Execution·Orchestration·Gateway 구현을 사용합니다.
- **Motion 설정 통합:** `arm_cell_moveit_config`의 설정·launch·Scene 도구·테스트를 `arm_cell_motion`으로 통합했습니다. MoveIt 설정은 `ros2_ws/src/motion/config/moveit/`에 있습니다.
- **공통 로봇 자산 분리:** `arm_cell_description`을 제거하고 URDF/Xacro, Mesh, 라이선스·출처를 `assets/robots/m0609_robotiq_2f85/`로 옮겼습니다. Motion은 ROS 실행에 필요한 자산을 설치 공간에 포함하며 Isaac은 공통 원본을 참조합니다. Isaac 전용 자산은 `infra/isaac_sim/assets/`에 유지합니다.
- **짧은 소스 폴더명:** `ros2_ws/src/`의 `arm_cell_` 폴더 접두사를 제거하고 중첩된 인터페이스 패키지를 `interfaces/`로 평탄화했습니다. ROS 패키지명, namespace, 메시지·Action 계약 및 실행 명령은 유지합니다.
- **Isaac 시작 오류 수정:** 자산 이동 후 발생한 `canonical Xacro digest does not match robot artifact provenance` 오류를 기존 로봇 생성 파이프라인으로 재생성해 해결했습니다. USD 해시는 동일하며 변경된 Xacro 출력·URDF 해시를 provenance에 반영했습니다. 실제 배포 자산을 검사하는 회귀 테스트를 추가했습니다.
- **경로 참조 갱신:** Bringup, Isaac entrypoint·UI Hub, 테스트, CI, Docker 자산 복사와 제3자 라이선스 안내를 새 구조에 맞췄습니다.

## 업그레이드

- 기존 ROS `build`/`install`에는 이전 소스 경로가 기록돼 있을 수 있습니다. 새 build/install 디렉터리에서 빌드하고 새 설치 공간을 source하세요. 예: `colcon build --build-base build-v0.3.2 --install-base install-v0.3.2` 후 `source install-v0.3.2/setup.bash`.
- Docker Compose 사용자는 저장소 루트에서 `docker compose up --build`로 이미지를 다시 빌드합니다.
- 소스 경로를 직접 참조하는 외부 스크립트는 새 폴더명에 맞춰 수정해야 합니다. ROS 명령의 `arm_cell_bringup`, `arm_cell_motion` 등 패키지명은 그대로입니다.
- 로봇 provenance는 Xacro 출력의 경로를 포함한 바이트를 검사합니다. 체크아웃 루트가 달라져 검증이 실패하면 `SFTWIN_PROJECT_ROOT`와 Isaac의 `m0609_cell/0_pre_build.py`에 설정된 프로젝트 루트를 확인하고 기존 자산 생성 절차를 실행하세요. Digest 검증을 비활성화하지 마세요.

## 검증 범위와 알려진 제한

- 새 소스 구조의 별도 build/install 공간에서 ROS 패키지 10개 빌드가 통과했습니다. 자산 통합 후 Docker 이미지 빌드도 통과했습니다.
- 최종 소스 경로에서 모델·provenance·MoveIt·Scene loader·Bringup·Isaac 설정 집중 테스트 101개, 추가 경로 연동 테스트 93개, recipe 테스트 19개가 통과했습니다. 이는 각각 실행한 테스트 결과이며 서로 중복 없는 총계라는 의미는 아닙니다.
- 사용자가 provenance 수정 후와 최종 폴더명 변경 후 live test 통과를 확인했습니다. 이 보고를 전체 Final Mission Acceptance의 개별 시나리오 증거로 확대하지 않습니다.
- 전체 테스트 모음은 완전 통과 상태가 아닙니다. 서식 검사, 이전 Action 경계를 기대하는 Motion 통합 테스트, Bringup 합성 시나리오 및 ROI 구성 기대값의 실패가 남아 있습니다.
- 실물 로봇 운전과 안전 등급 E-stop/STO 하드웨어 검증은 포함하지 않습니다.
