# SF-Twin ARM Cell v0.3.0 Release Notes

> v0.3.0 is an official release for engineering and simulation. It does not claim physical-robot support or full Mission Acceptance.

## Highlights since v0.2.0

- **Geometry-first Vision:** Uses RGB-D observations and known workpiece geometry, including shape hypotheses for partial observations. This does not guarantee detection in every scene or claim superiority over learned methods.
- **Mission and PnP task separation:** v0.2.0 already had Mission BT behavior and MoveIt planning, but PnP execution was not separated into a Task Execution layer. v0.3.0 adds `arm_cell_task_execution` and has Orchestration submit one task through the `ExecutePnp` ROS Action. The Task Execution BT and Motion runtime are composed in one `task_execution_node` process. This separates mission policy from PICK/PLACE task strategy; it does not add a standalone Task Execution process.
- **Reusable Motion execution:** Task Execution PICK/PLACE SubTrees compose common planning/execution BT leaf Actions, while Motion's internal Planning BT searches poses, IK, and paths and retries within the selected candidate. Task Execution owns ordering and transitions between candidates. This makes individual operations and task sequences easier to replace or compose independently; it does not establish measured performance or success-rate gains.
- **Vision/Motion geometry and occupancy boundary:** Vision returns observed geometry and eligible candidates; Task Execution decides candidate order and transitions. Motion evaluates movement feasibility for the candidate it receives and builds request-specific planning occupancy that excludes that selected candidate. Detection alone does not establish grasp feasibility or grant motion permission.
- **Recovery, Action lifecycle, and Safety ownership:** Orchestration coordinates mission-level retries and Safety-authorized recovery. Task Execution owns candidate transitions, task-internal recovery, and the single PnP Action terminal result. Motion owns selected-candidate planning retries plus individual movement execution, cancellation, terminal results, and actual stop evidence; Safety independently decides motion permission and direct stop requests.
- **Diagnostics and evidence:** Connects Acquisition snapshots with Vision/Motion planning evidence and expands component-level diagnosis. The public package does not include complete raw local diagnostic logs.
- **Simulator boundary:** v0.3.0 retains the existing boundary that keeps simulator-specific state and gripper realization behind shared ROS contracts. This supports replaceable implementations as a design direction; physical-robot adapters and operation have not been validated.
- **Technical records:** Publishes the nine Engineering Stories merged on 2026-10-30, with Private links and local artifact paths removed or converted to public-safe references.

See the [component architecture](../design/architecture/components.md), [Task Execution CDS](../design/components/task-execution/cds.md), [Motion Execution FDS](../design/components/motion/fds-motion-execution.md), [Orchestration–Task Execution ICD](../design/interfaces/icd-orchestration-task-execution.md), and [Vision/Motion occupancy story](../record/engineering-story/vision-to-motion-occupancy-ownership.md) for detailed contracts and evidence.

## Verification scope and known limitations

- The public Docker image build succeeded and compiled the 12-package `arm_cell_bringup` dependency closure. PR #12 installed TRAC-IK 2.0.1 in `/opt/trac_ik` and verified MoveIt pluginlib loading, ARM Cell IK plugin initialization, and `solve_type=Distance`. This did not calculate an IK solution for a target pose. With the full public checkout available, `colcon test --packages-up-to arm_cell_bringup` and `colcon test-result --all --verbose` failed with 2 errors, 133 failures, and 229 skipped across 1,887 reported results. CTest parent reports and leaf XML results are both included, so this is not a count of unique assertions. Formatting/style results include 89 uncrustify failures. Other failures include the synthetic full-cell nominal-mission mismatch, Motion/VDA/Gateway launch and timing boundaries, MoveIt configuration/scene-loader checks, and Vision Snapshot storage/metadata checks. Two error records are GTest processes that failed or timed out without writing result XML. The full-checkout run did not reproduce missing required assets. These test failures remain known limitations. Docker build and plugin initialization do not verify Isaac Sim live execution. The default MoveIt kinematics file selects KDL for the general MoveIt group, while the default operational profile selects TRAC-IK for PICK and Motion initializes that plugin separately. The Docker verification did not include the full Motion Launch.
- A separate Private-environment live record from 2026-10-30 confirms reset, SafetyRecovery, and GO_HOME after E-Stop, followed by Mission PnP resumption. A later approach ended with `BACKEND_UNAVAILABLE`; the complete Mission did not succeed. This evidence is separate from the Public Docker verification, limited to that revision and environment, and does not establish a general recovery rate.
- RGB-D acquisition records show both depth-reception gaps and missing synchronization callbacks. A common cause or complete resolution is unconfirmed.
- PLACE `WAYPOINT` remains experimental and incomplete. Do not present it as a completed path optimization or default operational strategy.
- No quantitative performance improvement is claimed because no comparable benchmark is available.
- Software Safety does not replace safety-rated E-stop/STO hardware. AMR navigation, physical-robot acceptance, and full VDA 5050 remain out of scope.
