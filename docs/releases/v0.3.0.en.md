# SF-Twin ARM Cell v0.3.0 Release Candidate Notes

> The current official release is v0.2.0. These v0.3.0 candidate notes are under Public Draft PR review and do not describe an official release until a separate publication step is complete.

## Highlights since v0.2.0

- **Geometry-first Vision:** Uses RGB-D observations and known workpiece geometry, including shape hypotheses for partial observations. This does not guarantee detection in every scene or claim superiority over learned methods.
- **Vision/Motion ownership:** Vision reports observed geometry; Motion constructs request-specific planning occupancy and excludes the currently selected candidate.
- **Reusable Motion execution:** Refines reusable Behavior Tree action boundaries and task strategy composition. PICK candidate ordering and occupancy-exclusion heuristics are implemented without a general scene-level performance claim.
- **Orchestration, Safety, and recovery:** Improves state ownership, failure recovery flow, and the boundary for resuming after Safety reset.
- **Diagnostics and evidence:** Connects Acquisition snapshots with Vision/Motion planning evidence and expands component-level diagnosis. The public package does not include complete raw local diagnostic logs.
- **Sim-to-Real direction:** Records the rationale for isolating simulator realization behind shared ROS contracts. This does not mean physical hardware adapters or robot operation have been validated.
- **Technical records:** Publishes the nine Engineering Stories merged on 2026-10-30, with Private links and local artifact paths removed or converted to public-safe references.

## Verification scope and known limitations

- The public Docker image build succeeded and compiled all 12 ARM Cell packages through `arm_cell_bringup`. PR #12 installed TRAC-IK 2.0.1 in `/opt/trac_ik` and verified MoveIt pluginlib loading, ARM Cell IK plugin initialization, and `solve_type=Distance`. This did not calculate an IK solution for a target pose. With the full public checkout available, `colcon test --packages-up-to arm_cell_bringup` and `colcon test-result --all --verbose` failed with 2 errors, 133 failures, and 229 skipped across 1,887 reported results. CTest parent reports and leaf XML results are both included, so this is not a count of unique assertions. Formatting/style results include 89 uncrustify failures. Other failures include the synthetic full-cell nominal-mission mismatch, Motion/VDA/Gateway launch and timing boundaries, MoveIt configuration/scene-loader checks, and Vision Snapshot storage/metadata checks. Two error records are GTest processes that failed or timed out without writing result XML. The full-checkout run did not reproduce missing required assets. These existing failures remain for investigation before publication. Docker build and plugin initialization do not verify Isaac Sim live execution. The default MoveIt kinematics file selects KDL for the general MoveIt group, while the default operational profile selects TRAC-IK for PICK and Motion initializes that plugin separately. The Docker verification did not include the full Motion Launch.
- A separate Private-environment live record from 2026-10-30 confirms reset, SafetyRecovery, and GO_HOME after E-Stop, followed by Mission PnP resumption. A later approach ended with `BACKEND_UNAVAILABLE`; the complete Mission did not succeed. This evidence is separate from the Public Docker verification, limited to that revision and environment, and does not establish a general recovery rate.
- RGB-D acquisition records show both depth-reception gaps and missing synchronization callbacks. A common cause or complete resolution is unconfirmed.
- PLACE `WAYPOINT` remains experimental and incomplete. Do not present it as a completed path optimization or default operational strategy.
- No quantitative performance improvement is claimed because no comparable benchmark is available.
- Software Safety does not replace safety-rated E-stop/STO hardware. AMR navigation, physical-robot acceptance, and full VDA 5050 remain out of scope.
