# SF-Twin ARM Cell v0.3.1 릴리즈 노트

> v0.3.1은 v0.3.0의 ROS 구조를 유지하면서 Isaac Sim과 ROS 런타임의 로컬·Docker 실행 경로를 보강한 엔지니어링 및 시뮬레이션 릴리즈입니다.

## v0.3.0 이후 주요 개선

- **두 가지 ROS 실행 방식:** ROS 2 Humble workspace를 호스트에서 빌드해 실행하는 방법과 Docker Compose가 이미지를 빌드하고 production bringup을 시작하는 방법을 제공합니다.
- **로그·진단 모드 선택:** 호스트 launch 인자 또는 Docker의 `ARM_CELL_LOG_LEVEL`과 `ARM_CELL_DIAGNOSTICS`로 `info`/`debug` 로그와 컴포넌트별 진단 기록 수집을 따로 선택할 수 있습니다. 기본 `info`는 선택적 진단을 끄고, 기본 `debug`는 ROS 진단 producer 전체를 켭니다.
- **Isaac Sim의 로컬 ROS 빌드 의존 제거:** `isaac_arm_cell.sh`가 씬, Timeline, UI Hub를 준비합니다. 호스트 ROS workspace의 `install`이 없으면 Docker에서 실행 중인 Material 및 Hub Python 3.10 sidecar에 localhost TCP로 연결합니다. Sidecar는 Isaac Sim이 나중에 연결해도 요청을 받을 수 있도록 listener로 동작합니다.
- **Docker DDS 데이터 전송:** Compose의 Fast DDS transport 기본값을 `UDPv4`로 지정했습니다. Docker가 publisher를 발견하면서도 메시지를 받지 못하던 문제를 해결했고, Isaac Sim의 RGB, depth, CameraInfo 및 simulation clock/joint-state 토픽 수신을 확인했습니다.
- **MoveIt planning-only 초기화:** Docker 이미지에 `moveit_simple_controller_manager` 실행 의존성을 추가하고 planning-only 프로파일에 controller manager 구성을 명시해 planning-only bringup을 보강했습니다.
- **실행 문서 통합:** 호스트 ROS 방식과 Docker Compose 방식을 README에 모았습니다. 자세한 구성 변경은 이 릴리즈 노트에서 다룹니다.

## 검증 범위와 알려진 제한

- Isaac Sim과 Docker Compose를 함께 실행해 정상 기동과 ROS 통신, RGB-D 토픽 전달을 확인했습니다. 호스트 ROS 2 Humble 방식도 README의 실행 절차로 제공합니다.
- 전체 ROS 테스트 모음, 모든 Mission/fault/recovery 시나리오, 전체 Final Mission Acceptance를 이 변경의 검증으로 주장하지 않습니다.
- v0.3.0에서 해결된 간헐적 RGB-D pair 취득 문제는 이후 버전에서도 해결 상태입니다. v0.3.1의 UDPv4 설정은 별도의 Docker DDS 토픽 전달 문제를 해결합니다. RGB-D 토픽 수신만으로 Vision 검출이나 PnP 성공을 보장하지는 않습니다. 과거 관측은 [RGB-D 취득 기록](../record/engineering-story/vision-rgbd-intermittent-acquisition-failure.md)에 남아 있습니다.
- 실물 로봇 운전과 안전 등급 E-stop/STO 하드웨어는 검증 범위 밖입니다.

## 이전 버전

[v0.3.0 릴리즈 노트](v0.3.0.ko.md)에는 미션, PnP, Motion 책임 경계와 당시의 검증 범위가 기록돼 있습니다.
