# SF-Twin ARM Cell v0.3.4 릴리즈 노트

> v0.3.4는 Vision/PICK 후보 선택, 부착 자재를 고려한 PLACE 복구, 실행별 기록과 런타임 관측성을 개선한 엔지니어링 및 시뮬레이션 릴리즈입니다.

## v0.3.3 이후 주요 변경

- **Vision과 PICK 탐색:** 지지된 적재 상단과 접근 가능한 파지 자세를 우선하고, 설정된 PICK pose 탐색 라운드를 소진하도록 개선했습니다. Tray 겹침에 따른 경사 지지 분류와 최종 직육면체 가설 선택을 보완하고 LOW 후보의 replay 근거를 보존합니다.
- **PLACE 복구:** 부착 자재를 반영한 경로 계획과 검증을 추가했습니다. PLACE 후보 소진 후 자재를 잡고 있으면 계획된 home 경유 재시도를 수행하며, 기본 재시도 횟수는 1회입니다. 그리퍼 inner knuckle과 부착 자재 사이의 허용 접촉도 반영합니다.
- **계획과 로그:** 계획 지연을 줄이고 단계별 진단을 보존합니다. 콘솔에 작업 진행과 결과를 표시하면서 상세 진단 기록을 유지합니다.
- **실행별 기록 통합:** `config/run_records.yaml`에서 기록 루트와 진단·스냅샷 디렉터리를 설정합니다. 연결된 기록을 같은 실행 디렉터리에 묶고, 첫 live test가 초기화 실행을 재사용하도록 했습니다. 진단 필드 이름과 해석 규칙을 정리하고 기존 reader 호환을 유지합니다.
- **Isaac 카메라와 환경:** 로컬 D455 자산을 포함하고 Play 전에 준비된 자산을 로드합니다. D455 calibration을 명시적으로 관리하며 Tray 시야와 로봇 옆 카메라 지지대 간격을 넓혔습니다.
- **로컬 빌드:** `ros2_ws/build-local.bash`에서 Dockerfile과 같은 TRAC-IK revision을 빌드하고 ROS workspace를 구성합니다.

## 업그레이드

- ROS 인터페이스와 런타임 변경이 함께 포함됩니다. 전체 ROS workspace와 Isaac 런타임을 함께 갱신하세요. Docker Compose 사용자는 저장소 루트에서 `docker compose up --build`로 다시 빌드합니다.
- 호스트 빌드는 README의 `bash ros2_ws/build-local.bash` 절차를 따르세요.
- 기록 경로는 기본 `.run_records`이며 `config/run_records.yaml`에서 변경합니다. 기존 기록을 자동으로 이동하지는 않습니다. Docker 실행 시 README의 UID/GID 설정과 기록 디렉터리 소유권 안내를 확인하세요.
- 자체 진단 분석 도구는 [관측 기록 ICD](../design/interfaces/icd-observability-records.md)의 필드 이름과 해석 규칙을 확인하세요.
- PLACE 재시도와 반환 동작은 [부착 자재 home 복구](../design/components/motion/place-payload-recovery.md)를 참고하세요. 기존 최종 자재 반환 이동은 충돌 검사 대상에서 제외됩니다.

## 검증 범위와 알려진 제한

- 이번 릴리즈 문서 갱신에서 CI와 같은 ROS 패키지 MIT 메타데이터 검사 및 Isaac Python 구문 검사, 변경 문서의 상대 링크와 diff 공백 검사를 수행했습니다.
- 전체 ROS 빌드·테스트 모음과 라이브 Isaac Mission acceptance는 이번 갱신에서 다시 실행하지 않았습니다. v0.3.3의 테스트 수치를 이번 버전의 검증 결과로 사용하지 않습니다.
- 실물 로봇 운전과 안전 등급 E-stop/STO 하드웨어 검증은 포함하지 않습니다.
