# SF-Twin ARM Cell v1.0.0 Release Notes

First 1.0 engineering and simulation baseline, covering changes since v0.3.4. This is not production-cell or safety certification.

## Changes since v0.3.4

- **Composition and runtime (#50, #56, #64–#73):** Bringup assembles component-owned configuration and validates Robot/Tool/Cell/Assembly identities, joints and Prim bindings. Motion consumes selected robot policies, tool contact/collision data and Cell-owned clearance references. Isaac uses Assembly-driven asset builds, selected scenes, articulation/HOME/drive bindings, tool capture, shared camera/supply geometry and common lifecycle services.
- **RB5 and layout (#75–#77):** Add the pinned upstream RB5-850E model with Robotiq 2F-85 while retaining M0609. Simulation maxForce=1000 and damping=50 address load holding and oscillation; these are not hardware ratings. User HOME is 0, 0, 90, 0, 90, 0 degrees; Return/Retract remain unchanged. PnP_CNC is the Cell/launcher display name; internal Prim paths remain compatible. Move the boom above the top beam, add a rear L bracket and supported cable tray, preserve optical camera pose and synchronize MoveIt collision geometry.
- **Vision and grasping (#44–#55, #57):** Recover inclined cuboids from plane maps; preserve tray-crossing observations and measured plane candidates; bound height-grid expansion; separate target ROI from tray calibration. Preserve steep height continuity and prioritize finger clearance. Add catalog-driven CNC materials and selectable supply, split depth-profile processing, use aperture-based grasp eligibility and accept configured target profiles. Gate detection on tray stability duration. Centralize post-release physics and wake detached material after enabling gravity. Align gantry/status hardware (#49).
- **Launcher and tooling (#58–#63, #74):** Provide the root launcher entry point, optional venv setup and revised bilingual operation guides. After the initial GUI introduction/revert, use shared ephemeral runtime snapshots with cleanup, supported-combination selection, duplicate protection, process ownership and lifecycle handling. Add xterm execution terminals, ROS debug selection, Qt dependency fixes and stale-bringup cleanup. Handle protected process cwd access and avoid duplicate CI runs.

## Upgrade

Rebuild the complete ROS workspace and source its overlay; Docker users run `docker compose up --build`. Follow README Qt/xterm setup and restart the launcher. Wait for Isaac initialization before starting ROS. Export a fresh selected Profile snapshot rather than reusing old exports. Run Pre Build for the first RB5 asset build. Migrate custom configuration against the component-owned profiles and Assembly contract; automatic legacy-schema conversion is not guaranteed. Existing run records are not moved automatically.

## Verification and limitations

The user reports successful live PnP, stable RB5 holding, satisfactory oscillation reduction and camera support placement. This is user observation, not quantitative performance or full-workspace certification. Focused Robot binding, scene, camera ownership, launcher and composition tests passed during implementation. This documentation update does not rerun the full ROS build or Isaac execution. Full Stop/Reset/E-Stop recovery and physical safety-rated E-stop/STO validation are not claimed. Use only supported deployment combinations; arbitrary Robot/Tool combinations and all material paths are not guaranteed.
