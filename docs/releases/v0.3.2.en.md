# SF-Twin ARM Cell v0.3.2 Release Notes

> v0.3.2 organizes ROS source directories and shared robot assets. It is an engineering and simulation release.

## Changes since v0.3.1

- **Removed leftover implementations:** Removed `arm_cell_motion_moveit2`, `arm_cell_orchestration_bt` (package name `arm_cell_bt`), and `arm_cell_integration` left after package renaming. The current Motion, Task Execution, Orchestration, and Gateway implementations provide these responsibilities.
- **Consolidated Motion configuration:** Moved configuration, launch files, Scene tools, and tests from `arm_cell_moveit_config` into `arm_cell_motion`. MoveIt configuration now lives in `ros2_ws/src/motion/config/moveit/`.
- **Shared robot assets:** Removed `arm_cell_description` and moved URDF/Xacro, meshes, licenses, and upstream notices to `assets/robots/m0609_robotiq_2f85/`. Motion installs the assets required by ROS; Isaac references the shared source. Isaac-specific assets remain in `infra/isaac_sim/assets/`.
- **Shorter source directory names:** Removed the `arm_cell_` prefix from directories under `ros2_ws/src/` and flattened the nested interface package into `interfaces/`. ROS package names, namespaces, message/Action contracts, and runtime commands are preserved.
- **Fixed Isaac startup provenance:** Regenerated artifacts through the existing robot builder to fix `canonical Xacro digest does not match robot artifact provenance` after asset relocation. The USD hash is unchanged; provenance now records the updated Xacro output and URDF hashes. Added a regression test against the shipped artifacts.
- **Updated path consumers:** Adjusted Bringup, Isaac entrypoints and UI Hub, tests, CI, Docker asset copying, and third-party notices for the new layout.

## Upgrading

- Existing ROS build/install directories may retain old source paths. Use fresh directories, for example `colcon build --build-base build-v0.3.2 --install-base install-v0.3.2`, then `source install-v0.3.2/setup.bash`.
- Docker Compose users should rebuild from the repository root with `docker compose up --build`.
- Update external scripts that reference source paths directly. ROS command package names such as `arm_cell_bringup` and `arm_cell_motion` remain unchanged.
- Robot provenance hashes the expanded Xacro bytes, including paths. If a different checkout root causes verification to fail, check `SFTWIN_PROJECT_ROOT` and the project root configured in Isaac's `m0609_cell/0_pre_build.py`, then run the existing asset preparation procedure. Keep digest verification enabled.

## Verification and known limitations

- All 10 ROS packages built in separate build/install directories using the final layout. A Docker image build also passed after asset consolidation.
- Focused model, provenance, MoveIt, Scene loader, Bringup, and Isaac configuration tests passed: 101 tests using the final source layout, 93 additional path-integration tests, and 19 recipe tests. These are separate runs, not a deduplicated total.
- The user reported passing live tests after the provenance fix and again after the final directory rename. These reports do not establish every scenario in Final Mission Acceptance.
- The full test suite is not entirely green. Formatting checks, Motion integration tests expecting the previous Action boundary, a Bringup synthetic scenario, and an ROI configuration expectation still fail.
- Physical-robot operation and safety-rated E-stop/STO hardware verification are outside this release's validation scope.
