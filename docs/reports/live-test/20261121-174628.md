# 첫 자재는 픽 위치에 도착했고 PLC는 작업 요청을 기다렸다

17:46 실행에서는 첫 공급이 성공했다. 마지막으로 관측된 PLC 단계는 22였다. 생산 이력에 첫 자재의 픽 슬롯 배정이 저장됐지만 예약은 없었고, 이 스트림이 참조한 PLC 어댑터 영수증에는 유휴 요청 번호 0만 남았다.

PLC는 위치 확정(`confirmed`), 슬롯 번호 일치(`boundSlot = cycle`), Mission 수락 가능(`admissionAvailable`)을 같은 스캔에서 확인해야 작업을 요청한다. 슬롯 배정 기록은 그중 공급 측의 판단을 보여준다. 라이브에서는 그 스캔의 HR6·HR7이 저장되지 않아 어떤 레지스터 값이 전이를 막았는지는 확정할 수 없다. [당시 PLC 전이 조건](https://github.com/dev-kibeom/sftwin-arm-cell/blob/95deac84f8155df7716a3f75ea8c3598b33700c0/ros2_ws/src/plc_adapter/codesys/PLC_PRG.prg.st#L101-L111)

**모의 PLC에서 구분한 원인.** Mission이 0.1초마다 수락 가능을 보내는 동안 Modbus 작업당 0.2초의 지연을 주었다. 설비 허가는 참이었지만 관측한 HR6·HR7 쓰기 네 번이 모두 `(0, 0)`이었다. 수락 표본 처리와 PLC 폴링이 같은 콜백 그룹에 묶여 수신 표본이 만료될 수 있었다. HR6이 0이면 미수신 또는 만료다. 반대로 HR6이 갱신되면서 HR7이 0이면 최근에 수신한 명시적 거절이다. 두 경우 모두 로봇이 대기하지만 조사할 곳이 다르다.

수정 후 같은 지연에서 HR6은 59, 65, 71, 77, 83으로 진행했고 HR7은 계속 1이었다. 해당 모의 실험은 어댑터의 전달 동작을 확인했다. 이후 라이브에서 작업 완료까지 검증한 결과는 이 사례에 포함되지 않는다. [수정과 회귀 테스트](https://github.com/dev-kibeom/sftwin-arm-cell/commit/7c5aa3dc007f4114a01efbdd3c5b535125c891d9)
