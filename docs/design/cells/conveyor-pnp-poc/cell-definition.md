# Conveyor Pick & Place Cell — Cell Definition (초안)

- **대상 Cell:** `conveyor-pnp-poc`
- **Owner:** Cell 설계 책임자 (선정 필요)
- **상태:** 설계 초안 / 구현 및 성능 실증 전

> 단일 컨베이어가 자재를 Pick 지점까지 운송하면 로봇이 출력 트레이로 이송하는 대표 공정이다. 목표는 설비 내부 물리 성능이 아니라 PLC–로봇 작업 간 정상·일시 중단·복구 계약의 가상 시운전이다. 공통 System HLD·MLD는 이 Cell에 종속되지 않는다.

## 목적·범위·요구사항

- **공정 목적:** 자재를 공급 지점에서 Pick 위치로 이동시켜 로봇이 배출 지점에 적재하고, 별도 작업자 개입 없이 다음 자재를 반복 처리한다.
- **무인 연속 생산의 정의:** 정상 운전과 기존 BT가 복구할 수 있는 일반 Motion 실패 등 사전 정의한 일시 고장은 수동 초기화 없이 생산을 이어간다. 관리자 Reset이 필요한 Safety 선점은 무인 복구 범위에서 제외한다. 상태를 확인할 수 없으면 해당 작업을 보류한다.
- **범위:** 설비 외부 I/O와 셀 공정 Gate, 상태 정합성, 로봇 작업 요청, 결과 확정, 반복 생산, 고장 주입. 장비 내부의 독자적인 복구·모터 제어 및 물리 안전기능의 최종 검증은 제외.
- **입력/출력:** 규격화된 단일 직육면체 자재 → 배출 트레이 슬롯에서 인수가 확인된 자재. PoC는 한 번에 **하나의 자재**를 처리한다.
- **진행 방식:** 정상 처리 후 공급 대기 자재가 있으면 자동으로 다음 Cycle로 이어진다. 작업자가 매 Cycle을 시작하지 않는다.

### 초기 검증 기준(제안; 구현 전 수치 확정)

| 요구 ID | 계약·판정 기준 | 측정 범위 |
|---|---|---|
| CD-R1 | 정상 조건에서 연속 Cycle이 완료되고 다음 Cycle로 자동 진입 | 초기 제안: 30 Cycle, 수동 조작 0회 |
| CD-R2 | 명령·응답 단절 및 중복 수신 후에도 동일 작업은 한 번만 실제 실행·확정 | Fault Injection 전 과정, 중복 Pick·완료 회계 0건 |
| CD-R3 | 사전 정의한 일시 고장 후 정상 조건이 복원되면 수동 초기화 없이 재개 | 승인된 시나리오별 시험 |
| CD-R4 | 관측이 불충분할 때 성공·완료를 추정하지 않으며 관련 명령을 보류 | 센서 불일치·상태 미확정 시나리오 |
| CD-R5 | 공정 조건 오류를 Safety 기능 검증으로 오인하지 않음 | 안전 시험은 별도 검증 경계 |

시간당 생산량, 실제 Cycle Time, 실물 Pick 성공률은 이번 PoC의 통과 KPI로 설정하지 않는다.

## 설비·레이아웃·자재 흐름

```mermaid
flowchart LR
    F[단일 자재 공급 위치] --> SI[투입 자재 감지]
    SI --> CV[컨베이어 CV-01]
    CV --> SP[Pick 위치 자재 감지 및 고정]
    SP --> RB[로봇 RB-01]
    RB --> OUT[배출 트레이의 고정 슬롯]
```

- 한 개의 컨베이어, 두 개의 경로 센서(`infeed_part_detected`, `pick_station_part_detected`), 위치 확인이 가능한 스토퍼, 한 대의 로봇과 배출 지점을 사용한다.
- 배출 트레이에는 자재 한 개를 담는 고정 슬롯이 있다. 이 Cell의 로봇만 슬롯에 적재한다. PLC는 로봇의 배치 사실과 실제 슬롯 점유로 인수를 기록한다. Commit 후 로봇이 배출 영역을 벗어나고 설비 동작이 허가되면 자재를 자동 배출한다. PLC는 빈 슬롯과 Mission 수락 가능 상태를 확인한 뒤 다음 자재를 공급한다. 초기화 시에도 실제 점유를 읽는다.
- 스토퍼는 Pick 지점에서 자재가 멈춘 상태를 표현한다. 로봇의 작업 경로와 간섭하지 않는 단순 배치로 구성한다.
- 실제 길이, 속도, 위치, TCP와 티칭 Pose는 Configuration / Calibration에서 관리하며 설계 본문에 고정하지 않는다.

| 설비·구역 | 기능 | 물리·배치 제약 |
|---|---|---|
| `CV-01` | 자재 이송·정지 및 실제 정지 피드백 제공 | 컨베이어 출구가 로봇 작업 공간에 위치. 정지 상태는 벨트 운동에서 관측 |
| `infeed_part_detected`, `pick_station_part_detected` | 진입 및 Pick 지점 감지 | 두 센서의 순서가 자재 이동 방향과 일치 |
| `STOP-01` | 정지 위치 고정 | 전진/후퇴 상태 확인 가능; 로봇 동선 간섭 회피 |
| `RB-01` | Pick & Place | 기존 로봇·툴 모델 재사용; 명목 티칭 Pose 사용 |
| 배출 트레이 / `tray_slot_occupied_feedback` | 고정 Place 위치의 슬롯 점유 관측 | 빈 슬롯은 자재 1개를 수용하며 인수 확인까지 자재를 유지 |

## Plugin 구성

| 역할 | 필요한 재사용 기능 | 구성 원본 / 비고 |
|---|---|---|
| PLC Runtime | CODESYS SoftPLC의 ST 공정 시퀀스 | PoC 선택, 공통 시스템 필수 요소 아님 |
| PLC Adapter | Modbus TCP를 공정 명령·상태 계약에 매핑 | 주소·폴링·시간 값은 별도 구성 |
| Conveyor / Stopper | Isaac Sim 물리 장치 및 가상 I/O Plugin | 공식 에셋 우선, 자체 에셋은 공용 라이브러리 |
| Sensor | 위치/점유 관측 및 Fault Injection | 입력 변화는 가상 설비에서 생성 |
| Robot | 기존 ROS 2 / BT / Motion 및 Robot Backend | 기존 ARM Cell 계약 재사용 가능 범위 검토 필요 |
| Target Source | 정적 Pick 위치에 대한 Configured Supply 티칭 또는 기존 Vision 기반 PnP | 적용 경계는 [Cell Control](cell-control.md)의 구현 선행 확인 사항 참조 |
| Grip | 상면 수직 흡착·해제 | Tool은 실제 결합 대상과 예약 자재를 대조한다. 트레이 슬롯 점유는 설비가 별도로 관측 |

Cell별 설정은 Plugin 선택, 설비 배치, 센서/명령 매핑과 명목 Pose를 참조한다. 새로 필요한 범용 기능이 있는 경우에만 System 설계를 별도로 보완한다.

## 설비별 시뮬레이션 수준과 실물 검증 경계

| 설비/기능 | 모사 수준·가정 | 시뮬레이션 검증 | 실물/PoC/FAT/SAT에서 검증 |
|---|---|---|---|
| 컨베이어 | Kinematic/Physical 자재 이동, 명령 기반 정지 | 정지·재개, 센서 관측, 공정 Gate | 실제 모터 속도·토크·가감속·부하 |
| 스토퍼 | Joint 구동과 종단 상태 | 진입/후퇴 및 다음 작업 허가 | 실제 공압 응답·스트로크·센서 설치 |
| 로봇 | 명목 경로 + 흡착컵 결합 | 요청/완료·복구 협력 및 간섭 사전 검토 | 티칭·TCP·경로 간섭·파지 성공 |
| PLC | 가능한 실제 ST 프로그램을 SoftPLC에서 실행 | 상태 전이·명령·복구·재동기화 | 실제 PLC 하드웨어, Field I/O, 통신·스캔 타이밍 |
| 센서 | 위치 기반 모의 신호 + 오류 주입 | 순서 위반·응답 소실·지연 대응 | 설치 오차·응답 특성·내구성 |
| 안전 | 논리적인 요청 정지/재개 시나리오만 모사 | 업무 Gate가 안전 권한을 우회하지 않는지 | 실제 Safety PLC, E-Stop/STO, 위험성 평가, 재기동 시험 |

## 설계 경계

- 자산/에셋 관리 정책의 구축은 이 Cell 설계 작업과 별도다.
- 실제 PLC 선택이 달라지면 Adapter와 배포 구성은 달라질 수 있으나 공정 계약은 유지하는 것을 목표로 한다.
- 구동기의 내부 고장 복구는 장비 제조사의 영역이며 Cell은 외부 상태와 요청·응답 계약만 시험한다.
