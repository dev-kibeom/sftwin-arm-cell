# RB5-850E 조합 실행 및 사용자 라이브 검증

지원 조합은 M0609 + Robotiq 2F-85 + `isaac_m0609`(기본값),
RB5-850E + 동일 Tool + 동일 Cell이다. RB5는 **구현·자동 검증 대상이며 라이브 검증 전**이다.
Launcher의 Robot에서 `rb5_850`을 선택하면 그 상태가 표시된다. 임의 Robot/Tool 교차 조합은 지원하지 않는다.

모델 출처·버전·라이선스·실물 사양과의 구분은
[UPSTREAM](../../assets/robots/rb5_850/third_party/rbpodo_description/UPSTREAM.md)을 참조한다.
현재 RB5 Profile의 HOME·Return은 로컬 simulation 자세다. upstream effort=10은 그대로
보존하며 제조사 정격 torque로 주장하지 않는다. Isaac drive의 하중 유지·포화 여부는 라이브 확인 대상이다.

## 준비 및 재현 가능한 자동 검사

저장소 루트에서 실행한다. ROS workspace 빌드는 [README](../../README.md#arm-cell-실행-방법)를 따른다.

```bash
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
export SFTWIN_PROJECT_ROOT="$PWD"
export ARM_CELL_RUNTIME_CONFIG="$PWD/.run_records/rb5_850_runtime_configuration.json"
PYTHONPATH="$PWD/ros2_ws/src/bringup${PYTHONPATH:+:$PYTHONPATH}" \
  python3 ros2_ws/src/bringup/scripts/export_runtime_configuration \
  --profile ros2_ws/src/bringup/config/rb5_850_profile.yaml \
  --output "$ARM_CELL_RUNTIME_CONFIG"

# 공통 Pre Build를 실행하고, Timeline 없이 USD Binding/HOME/Drive/Tool을 검사한다.
"${ISAAC_SIM_ROOT:-$HOME/isaac_sim}/python.sh" -u \
  infra/isaac_sim/scripts/verify_selected_model.py --build
```

예상 결과: `Complete robot asset build finished`와
`STATIC MODEL PASS: rb5_850_robotiq_2f85; Timeline was not started`.
Articulation Root는 선택된 Cell의 Robot Prim 아래 `root_joint`, Base는 `base_link`다.
기존 Cell의 `/World/SF_Twin_Cell/m0609` 경로 이름은 그대로지만 참조 USD는 선택한 Assembly다.
각 arm Joint의 drive type/maxForce도 출력한다. RB5의 생성 결과는 acceleration drive,
maxForce=10이며 하중에서 충분한지는 라이브 확인 대상이다. 이는 관절 구동 성공 증거가 아니다.
M0609 회귀는 `--profile`을 `operational_profile.yaml`로 바꾸고 다른 Export 파일을 사용한다.
기존 M0609 USD는 이 작업에서 다시 생성할 필요가 없다.

```bash
# 선택된 두 모델의 실제 MoveIt/KDL/Collision 검사 (빌드 후)
colcon test --base-paths ros2_ws/src --build-base ros2_ws/build \
  --install-base ros2_ws/install --packages-select arm_cell_motion \
  --ctest-args -R test_selected_model --output-on-failure
colcon test-result --test-result-base ros2_ws/build/arm_cell_motion --verbose
```

자동 검사는 URDF/SRDF·관절 순서·Mesh 로드, 설정 자세의 Limits·Self-collision,
선택 planning group의 HOME 대 Cell 충돌, Tray 중심·CNC 목표의 충돌 없는 정적 IK를 확인한다.
고정 Base와 pedestal riser의 접촉은 두 모델 모두 존재하며, 움직이는 `arm` planning group 검사와
구분한다. ACM이나 Cell Geometry를 바꾸지 않는다. Tray 전체, 경로의 연속성, 접근·후퇴·Attach 상태는
이 정적 IK 검사의 범위가 아니다.

## 사용자 라이브 순서

GUI와 수동 실행 중 하나만 사용한다. 새 실험은 런타임을 모두 종료하고 시작한다.

1. `python3 launcher.py`에서 Robot=`rb5_850`, Tool=`robotiq_2f85`,
   Cell=`isaac_m0609`, Backend=`Isaac / simulation`을 선택한다.
   `라이브 검증 전` 표시를 확인한다. 기본 선택은 계속 M0609다.
2. 위 Pre Build 완료 후 `Isaac 시작`을 누른다. Launcher가 선택한 Profile을 별도로 Export하여
   동일 snapshot을 Isaac·ROS에 전달한다. 수동 실행이라면 위 Export를 사용한다.

   ```bash
   bash infra/isaac_sim/scripts/isaac_arm_cell.sh --runtime-config "$ARM_CELL_RUNTIME_CONFIG"
   # Isaac 초기화 완료 후 별도 터미널 (같은 Export 경로·ROS domain 사용)
   source /opt/ros/humble/setup.bash
   source ros2_ws/install/setup.bash
   ros2 launch arm_cell_bringup arm_cell.launch.py profile:="$ARM_CELL_RUNTIME_CONFIG"
   ```

3. 관절 이름 `base, shoulder, elbow, wrist1, wrist2, wrist3`, Joint axis와 조립 방향을 확인한다.
   초기 HOME는 Profile의 `robots/rb5_850/home.yaml`과 비교한다. 과도한 흔들림·축 처짐·Drive 포화가
   없는지 확인하고, 목표 Target만으로 이동·안정화를 PASS 처리하지 않는다.
4. ROS 시작 전 빈 작업 공간에서 Script Editor로 공통 Tool의 OPEN/CLOSE를 확인할 수 있다.
   명령은 한 번에 하나씩 실행하고 실제 손가락 동작을 관찰한다. 작업 중에는 직접 호출하지 않는다.

   ```python
   from isaac_runtime import runtime_workflow
   tool = runtime_workflow.startup_namespace['gripper']
   tool.close()
   # 동작 완료와 빈 손가락 상태 확인 후 별도로 실행
   tool.open()
   ```

5. Launcher의 `ROS 2 시작` 후 다음 Topic을 확인한다.

   ```bash
   ros2 topic echo /isaac/joint_states --once
   ros2 topic echo /joint_states --once
   ros2 topic echo /motion/state --once
   ros2 topic echo /safety/state --once
   ros2 topic echo /gripper/status --once
   ros2 topic echo /joint_commands
   ```

   State에 선택 Robot의 6개 이름이 나타나야 한다. Command는 실제 Motion 요청 중 관찰한다.
   State/Command의 동일 Robot identity와 최신 시간, 실제 Joint 변화가 함께 일치해야 한다.
6. Tray와 CNC Fixture의 실제 위치·Robot 및 설비 충돌·카메라 FOV를 확인한다.
   정적 IK 결과가 실제 접근·후퇴를 보장하지 않는다. 자재를 놓기 전 HOME 복귀와
   Tray/CNC 접근 공간을 확인한다. Camera·Supply 배치는 기존 Cell과 같다.
7. UI Hub `External Handoff Trigger`에서 `Material type=TestCube`, `Quantity=1`,
   `Random Drop`으로 공급한다. 공급 완료→Vision→PICK→Holding→CNC PLACE→release를 관찰한다.
   Robotiq Attach/Detach와 물체가 Fixture에 남는 상태까지 확인한다.
8. 단일 자재 성공 후 `Quantity`를 늘려 같은 공급·미션 흐름의 다자재 PnP를 확인한다.
   Tray 가장자리·CNC 주변 접근 실패는 해당 자재 위치와 진단 기록을 함께 남긴다.
9. 실행 중 Stop/Reset과 UI Hub의 E-Stop 입력·해제·별도 Safety Reset을 기존 절차대로 검사한다.
   Timeline Stop은 Safety Reset이 아니다. Stop 후 재실험은
   ROS 종료→Timeline Stop→`1_before_play.py`→Play→`2_after_play.py`→ROS 시작 순서다.
   마지막에 Robot을 M0609로 되돌려 동일 기본 실행·HOME·PnP·복구 회귀를 확인한다.

## 완료 상태의 구분

Codex의 자동 검증은 모델·설정·빌드·정적 USD/Graph/Tool 연결·MoveIt 범위다.
**실제 RB5 관절 구동, HOME 이동/유지, Robotiq 구동 및 Attach/Detach, Tray PICK,
CNC PLACE, 전체 PnP, Stop/Reset·E-Stop 복구는 사용자 라이브 검증 전**이다.
라이브 관측 전에는 Launcher나 문서의 상태를 검증 완료로 변경하지 않는다.

## Simulation drive tuning

`ros2_ws/src/motion/config/robots/rb5_850.yaml`의
`isaac.joint_drive_max_forces`는 선택된 arm joint의 USD angular drive maxForce를
Scene 구성 후 Play 전에 덮어쓴다. 생략한 관절은 import 값을 유지한다.
현재 1000은 HOME 처짐 비교용 simulation 시험값이며 제조사 정격 torque가 아니다.
Drive type은 변경하지 않는다. upstream URDF effort=10도 보존한다.
위의 maxForce=10 설명은 override 전 import 산출물에 해당한다.

값 변경 후 Isaac과 ROS를 종료하고 Profile을 새로 export해 재시작한다.
이 runtime override만 바꾼 경우 USD Pre Build는 필요하지 않다.
HOME 도달 오차, 유지 중 처짐, 진동과 이동 중 충돌을 실제 관측해야 하며,
설정 적용만으로 HOME 유지나 PnP 검증 완료를 주장하지 않는다.
